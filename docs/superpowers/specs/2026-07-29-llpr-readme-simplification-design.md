# LLPR README 简化设计

## 目标

把 `Uncertainty_Quantification/LLPR/README.md` 从审计式说明改为容易查阅的使用手册，同时保留用户要求的逐文件对应关系。

成功标准：

- 当前正式迁移目录中的 64 个文件全部逐项列出；
- 每个文件只解释“文件作用”和“与旧文件的关系”；
- 删除不利于普通使用者理解的哈希、identity、条件数、内部分类、详细数值审计和数学推导；
- 删除 `details.npz` 的 44 字段说明以及 `curvature.npz` 的内部字段表；
- README 保留最少且足够的运行说明；
- 文档描述继续以当前真实文件、代码和数据为依据。

## 文档结构

README 使用以下结构：

1. **用途**
   - 简述 LLPR 的用途；
   - 说明代码支持直接指定和验证集拟合两种 `eta` 模式；
   - 说明当前正式迁移成果使用固定 `eta`。

2. **常用命令**
   - 激活 `upet_new`；
   - 进入仓库；
   - 运行正式成果验证；
   - 简要保留未来重新计算入口，不展开实现细节。

3. **目录说明**
   - `curvature/`：曲率结果；
   - `calibration/`：校准结果；
   - `evaluation/`：测试评估结果；
   - `plots/`：当前为空；
   - `legacy_raw/`：原样保留的旧成果。

4. **逐文件说明**
   - 按目录拆成多个三列表格；
   - 表格列固定为“文件”“作用”“与旧文件的关系”；
   - 覆盖全部 12 个规范化文件和 52 个 `legacy_raw` 文件。

5. **结果边界**
   - 正式迁移没有重新加载模型或重新执行完整计算；
   - 小规模链路测试结果已删除；
   - 当前目录只保留正式迁移成果。

## 逐文件写法

### 规范化文件

12 个规范化文件逐项列出：

- 迁移管理文件（如 manifest 和 inventory）写明“迁移后新增，无一一对应旧文件”；
- 规范化数据文件写明它来自哪些旧结果文件；
- 摘要和预览文件写明它们是根据旧正式结果整理生成；
- 不展开数组字段、shape、公式、哈希或 identity。

### `legacy_raw` 文件

52 个旧文件逐项列出：

- 作用限制为一句通俗说明；
- 旧文件关系统一使用“旧目录同路径文件，原样保留”；
- smoke 结果明确写成“小规模测试结果”；
- 配套输出不完整或未列入正式绘图摘要的文件，使用简短自然语言提示；
- 不展示 `classification`、`formal_source`、SHA-256 或文件大小。

## 可读性规则

- 每个文件说明只表达一个主要用途；
- 避免解释实现内部变量；
- 技术名称只保留用户定位文件所必需的部分；
- 不重复列出同一统计值；
- 使用目录小标题帮助查找，避免单个 64 行大表；
- README 目标是“知道该看哪个文件”，不是替代迁移审计报告。

更详细的迁移证据继续由 `MIGRATION_REPORT.md` 承担。
