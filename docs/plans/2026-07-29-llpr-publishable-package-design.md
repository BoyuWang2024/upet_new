# LLPR 可直接发布版本整理设计

日期：2026-07-29

状态：已确认，等待实施

## 1. 最终目标

将 `Uncertainty_Quantification/LLPR` 整理为一套可以直接发布的新版本：

- 新代码能够独立完成 LLPR 曲率构建、η 校准、测试评估和绘图。
- 同时支持“直接指定 η”和“根据验证集拟合 η”两种模式。
- 当前正式结果继续使用直接指定的 η，不重新进行完整计算。
- 已有正式数值结果转换为新代码统一使用的产物格式。
- 发布后的代码和正式结果不依赖外部旧目录。
- 发布内容不包含迁移说明、旧代码副本、旧配置、日志、缓存或重复结果。

## 2. 已确认的边界

1. 外部现有代码和结果目录保持原状，整理过程中只读访问。
2. 当前正式数值结果不得发生改变。
3. 最终正式结果目录统一为：

   `Uncertainty_Quantification/LLPR/outputs/matpes_r2`

4. 正式结果中不保留：

   - `legacy_raw/`
   - `inventory.json`
   - 来源说明文件
   - 旧目录路径
   - `legacy_import`、`legacy_fixed_ridge` 等迁移字段

5. 当前正式结果对应“直接指定 η”模式。
6. 小规模测试产生的结果必须在验证完成后删除。

## 3. 方案选择

### 3.1 采用方案

采用“重新发布精简正式产物”的方式：

- 只保留新代码实际读取的标准化结果。
- 重新生成不带迁移语义的清单。
- 正式数值数组保持完全一致。
- 删除新项目中为迁移临时保留的全部原始副本。

### 3.2 未采用方案

未采用以下方式：

- 在现有目录内直接删除 `legacy_raw/`：会使当前清单和校验逻辑失效。
- 继续保留少量旧输入文件：仍然存在重复数据和来源耦合，不适合作为最终发布版本。
- 重新运行完整计算：耗时较长，而且当前任务要求复用已经确认的正式数值成果。

## 4. 最终正式结果结构

最终只保留 11 个文件：

```text
outputs/matpes_r2/
├── manifest.json
├── curvature/<自动编号>/
│   ├── manifest.json
│   ├── curvature.npz
│   └── diagnostics.json
├── calibration/<自动编号>/
│   ├── manifest.json
│   ├── candidates.json
│   └── summary.json
└── evaluation/<自动编号>/<自动编号>/
    ├── manifest.json
    ├── details.npz
    ├── summary.json
    └── preview.json
```

各文件作用如下：

| 文件 | 作用 |
|---|---|
| 根目录 `manifest.json` | 描述一次完整实验，并连接曲率、校准和评估阶段。 |
| `curvature.npz` | 保存能量、力及联合曲率矩阵等正式数值。 |
| `curvature/diagnostics.json` | 保存曲率维度、样本数量和可用诊断状态。 |
| `curvature/manifest.json` | 描述曲率产物的模型、数据、参数和文件信息。 |
| `calibration/candidates.json` | 保存 η 校准候选结果。 |
| `calibration/summary.json` | 保存最终采用的 η 和校准统计。 |
| `calibration/manifest.json` | 描述校准阶段依赖的曲率与验证数据。 |
| `evaluation/details.npz` | 保存逐结构、逐原子或逐分量的预测、误差与不确定性。 |
| `evaluation/summary.json` | 保存正式测试集上的汇总指标。 |
| `evaluation/preview.json` | 保存便于快速查看的小规模结果预览。 |
| `evaluation/manifest.json` | 描述评估阶段的依赖、参数和结果文件。 |

`<自动编号>` 由代码根据实际内容和参数生成，用于关联阶段和防止结果混用；用户不需要手动填写。

绘图结果不属于上述 11 个正式数值文件。绘图命令只读取
`outputs/matpes_r2`，并将图片和绘图统计写入独立目录，不能修改正式结果目录。

## 5. 清单与元数据

发布清单采用统一的中性格式：

- 保留模型、checkpoint、数据集、参数、维度、阶段依赖和文件校验信息。
- 删除 `origin`、`source_origin`、旧目录路径及所有迁移专用字段。
- 根清单的阶段名称使用中性名称，不再使用 `legacy_import`。
- 缺失的历史诊断只记录为通用的 `unavailable`，不解释其来源。
- 新生成的自动编号不得依赖外部旧目录或来源文件清单。

清单编号可能因字段精简而改变，但数值结果不得改变。

## 6. 新代码整理

### 6.1 删除迁移专用内容

删除：

- `llpr/legacy.py`
- `tests/test_legacy.py`
- `configs/import_legacy.yaml`
- `configs/plot_legacy.yaml`
- `MIGRATION_REPORT.md`
- CLI 中的 `import-legacy` 命令
- `legacy_raw` 和 `inventory.json` 专用校验代码

### 6.2 修改现有模块

- `llpr/artifacts.py`
  - 删除 `legacy_raw` 路径接口。
  - 删除旧文件清单校验。
  - 完整验证只检查根清单、阶段清单及其声明的正式文件。

- `llpr/cli.py`
  - 删除导入旧产物的入口。
  - 保留构建、校准、评估、绘图和验证入口。

- `llpr/plotting.py`
  - 不再要求评估清单包含来源字段。
  - 只根据正式评估结果生成图和绘图统计。
  - 将绘图结果写到配置指定的独立输出目录，不能写回正式结果目录。

- `llpr/checkpoint.py` 及相关测试
  - 将仅用于迁移描述的命名改为模型契约等中性命名。
  - 保留实际需要的 checkpoint 兼容性检查。

- `llpr/curvature.py`、`llpr/calibration.py`、`llpr/inference.py`
  - 使用统一的发布清单结构。
  - 不再写入来源字段。

### 6.3 保留的正式功能

- 模型和 checkpoint 检查。
- 数据集读取。
- 能量和力 readout。
- 曲率矩阵构建及断点恢复。
- 固定 η 校准。
- η 拟合。
- 测试集评估。
- 结果绘图。
- 产物清单、原子写入和完整校验。

新增中性的正式绘图配置，读取 `outputs/matpes_r2`，输出到正式结果目录之外。

## 7. 两种 η 模式

### 7.1 直接指定 η

配置文件：`configs/gpu_full_fixed.yaml`

- 当前正式 `matpes_r2` 使用这种模式。
- η 由配置直接给出。
- 新代码读取现有曲率和校准结果后可直接进行评估与绘图。
- 将来需要时也可以使用新代码重新完成全部计算。

### 7.2 拟合 η

配置文件：`configs/gpu_full_fit.yaml`

- 根据验证集拟合 η。
- 输出到独立实验目录，不能覆盖当前正式的 `matpes_r2`。
- 其余曲率、评估、绘图和验证流程与指定 η 模式一致。

## 8. 数据流

```text
checkpoint + 训练集
        ↓
曲率构建
        ↓
验证集 + η（直接指定或拟合）
        ↓
校准
        ↓
测试集
        ↓
评估
        ↓
绘图（独立输出目录）
```

每个阶段只读取已经完成并通过验证的上游产物。两种 η 模式使用相同的校准输出结构，因此评估和绘图模块不需要区分 η 的来源。

绘图是对评估结果的只读消费，不属于 `matpes_r2` 正式产物树的一部分。

## 9. 正式结果整理流程

1. 记录外部现有结果目录的文件状态，全程只读。
2. 在临时目录构建新的 `outputs/matpes_r2`。
3. 复制并标准化当前已经确认的正式数值产物。
4. 删除迁移专用元数据，生成中性清单和新的自动编号。
5. 对新旧产物执行逐项数值比较。
6. 对临时 `matpes_r2` 执行完整验证。
7. 所有检查通过后再发布到正式路径。
8. 删除新项目中的 `outputs/matpes_r2_legacy`。
9. 删除小规模测试结果和整理过程的临时文件。
10. 再次核对外部现有目录，确保没有发生变化。

## 10. 数值一致性要求

以下内容必须保持一致：

- NPZ 中的数组名称。
- 每个数组的形状和数据类型。
- `curvature.npz` 的所有数值。
- `details.npz` 的所有数值。
- 当前指定的 η。
- 校准统计和测试统计中的数值。
- 训练、验证、测试的样本数量。
- 能量、原子和力分量数量。

允许变化的内容仅包括：

- 自动编号。
- 清单中的文件路径。
- 已确认删除的迁移字段。
- 不影响数值含义的中性状态文字。

NPZ 使用逐数组精确比较，JSON 使用结构化比较；不能只比较文件大小。

## 11. 测试与验证

所有命令均在 Ubuntu 中使用 `conda activate upet_new` 后执行。

### 11.1 自动测试

- LLPR 单元测试。
- 配置解析测试。
- CLI 测试。
- 产物写入与完整校验测试。
- 固定 η 校准测试。
- η 拟合测试。
- 评估与绘图测试。

删除或改写所有依赖迁移目录、`legacy_raw` 和来源字段的测试。

### 11.2 小规模全链路

使用现有 CPU 小规模配置分别验证：

1. 指定 η：

   曲率构建 → 固定 η 校准 → 评估 → 绘图 → 完整验证。

2. 拟合 η：

   曲率构建 → η 拟合 → 评估 → 绘图 → 完整验证。

两条链路都必须成功，产生的测试结果在检查结束后删除。
测试图片同样写入临时目录，并在验证后删除。

### 11.3 正式产物验证

- `outputs/matpes_r2` 只能包含设计规定的 11 个文件。
- 完整校验必须独立通过。
- 正式数值与整理前逐项一致。
- 代码和配置中不得再引用旧目录。
- 发布结果不得依赖 `legacy_raw` 或 `inventory.json`。
- 外部现有目录在整理前后保持一致。

## 12. 异常处理与回退

- 临时整理目录没有全部通过验证前，不替换正式目录。
- 任一数组、统计值、样本数量或参数不一致时立即停止。
- 任一自动测试或小规模全链路失败时立即停止。
- 失败时保留当前正式产物用于排查，不删除有效结果。
- 正式发布采用临时目录完成后再切换的方式，避免出现半成品。
- 只有新的 `matpes_r2` 验证通过后，才删除新项目中的 `matpes_r2_legacy`。
- 无论成功或失败，都不得修改外部现有代码和结果目录。

## 13. README 设计

`Uncertainty_Quantification/LLPR/README.md` 保持简洁，包含：

- LLPR 的用途。
- 环境、数据和 checkpoint 准备。
- 指定 η 与拟合 η 的区别和运行方法。
- 构建、校准、评估、绘图和验证命令。
- 正式绘图配置以及独立绘图输出目录。
- 当前正式结果使用直接指定的 η。
- 逐文件说明新代码、配置和 11 个正式结果文件的作用。

README 不包含：

- 旧文件对应关系。
- 迁移过程。
- 来源说明。
- 哈希明细。
- `legacy` 相关内容。

## 14. 验收标准

满足以下全部条件后，才视为完成：

1. 新 LLPR 代码可以独立发布和使用。
2. `outputs/matpes_r2` 仅包含 11 个正式文件。
3. 正式数值与整理前完全一致。
4. 当前正式结果明确使用直接指定的 η。
5. 指定 η 和拟合 η 两条小规模全链路均通过。
6. LLPR 自动测试全部通过。
7. 正式产物完整校验通过。
8. 所有测试产物和临时文件已删除。
9. 新项目中的旧迁移产物已删除。
10. 外部现有目录保持不变。
11. README 可以作为发布版本的直接使用说明。
